## Резервирование и регулярный контроль

[SCRAM restore](https://github.com/Xrenus1991/TelegramMonitor/actions/runs/42167432083): 5538 сообщений, роли, memberships, права SELECT/UPDATE восстановлены с ownership/ACL. Проверка выполнялась в disposable PostgreSQL без сети и опубликованных портов. Производственные пароли и права не менялись.

[PR31](https://github.com/Xrenus1991/TelegramMonitor/pull/31) объединён. Расширенный тест запускается раз в сутки, после ошибки — не чаще чем через шесть часов. Общая блокировка и PAUSE соблюдаются. Лимиты восстановления сервисов не менялись.

[Фактический cron](https://github.com/Xrenus1991/TelegramMonitor/actions/runs/42168763698): 05:22 UTC, exit_code=0, roles_exit_code=0; хеши трёх установленных скриптов совпали с репозиторием. Дампы, credentials и защищённые снимки остались только на сервере.

Обнаружен отдельный сбой checkout GitHub Actions: старый рабочий каталог не являлся доступным git-репозиторием. Исправлено выделением каталога autonomy-${{ github.run_id }} без изменения прав. [Повторный запуск](https://github.com/Xrenus1991/TelegramMonitor/actions/runs/42169347636) успешно завершён 05:35:55 UTC на нужном runner; AUTONOMY_OK, рестарты не потребовались.

## Группа и история

[Production-проверка](https://github.com/Xrenus1991/TelegramMonitor/actions/runs/42167852709): одна ранее выбранная группа, два цикла синхронизации collector; новых локальных сохранений в disabled-окне нет. Состояние источника возвращено. Запрос 20 последних сообщений прошёл pending → done, started_at установлен. Checkpoint не сброшен, история не удалялась, worker pending/processing по источнику равны нулю.

Ноль сохранений сам по себе не доказывает блокирование сообщений, появлявшихся в Telegram: наличие такого трафика отдельно не установлено. Реальный запрос на 1000 не выполнялся; границы 1000/1001 проверены API и PostgreSQL-контрактами.

## Переподключение и регрессия

[PR32](https://github.com/Xrenus1991/TelegramMonitor/pull/32) сохраняет воспроизводимые проверки в main. [Полный набор с реальным TCP](https://github.com/Xrenus1991/TelegramMonitor/actions/runs/42169110324) успешен: loopback-peer закрывает первый сокет, установленная библиотека Telethon автоматически подключается повторно. Синтетический AuthKey, без аккаунта, сессии и внешнего Telegram. Это проверка транспорта библиотеки, а не принудительный обрыв боевого collector.

[Браузер и API на production](https://github.com/Xrenus1991/TelegramMonitor/actions/runs/42168428311): 21 источник, поиск и пагинация, сброс фильтра, popup fallback, история Sherlock, свежий job octocat только на GitHub; JSON/CSV/XLSX/TXT скачаны. Отдельный браузерный контейнер ограничен 512MiB/0.5CPU, удалён после теста. Проверены auth401, validation422, comments/stats/diagnostics/signals/daily/duplicates, 1190 строк с sender_user_id и ru-context-v2.

Deep: 9 завершённых исторически, 32 ожидающих; за текущие сутки выполнено 3 при лимите 3/сутки. Ожидание при исчерпанном лимите не является доказательством зависания. Месячный предел $5 и дневной предел deep не изменены. Внешний счёт провайдера отдельно не аудировался.

## Язык и перевод

[Language CI](https://github.com/Xrenus1991/TelegramMonitor/actions/runs/42169110503): Lingua2.2.0, Apache2.0, только RU/AM/EN. 13 синтетических примеров, включая unknown для короткого, смешанного и бессодержательного ввода; 0.011s с загрузкой, peak RSS23.7MiB на GitHub runner. Это ограниченный корпус, а не оценка качества на реальной переписке.

[Argos index](https://github.com/argosopentech/argospm-index/blob/ff90de60728f7c1338ff6b75974e4c89b2442d22/index.json): в проверенных 100 пакетах есть ru↔en1.9, нет пакетов с hy. Argos не выбран для полного RU/AM/EN и на сервер не установлен.

[Реальный перевод](https://github.com/Xrenus1991/TelegramMonitor/actions/runs/42169061725): один bounded-вызов существующего gpt-6-luna через штатные reserve/settle и paid_call, 142 входных/90 выходных токенов. «Good morning.» → «Доброе утро.», «Բարև աշխարհ։» → «Привет, мир.», русский текст сохранён. Использованы только синтетические предложения. Лимиты и аккаунты не менялись.

Следующая реализация: адаптер определения языка и перевода с отдельными original/translated полями, версией и кэшем; адресные unit/API-тесты, stage, ресурсная проверка и конкретный откат перед production. Пять направлений не объявляются полностью завершёнными: ограничения указаны в таблице.
