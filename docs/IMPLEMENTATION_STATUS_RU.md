## Безопасное включение

- `CLOUD_DISCOVERY_INCLUDE_CHANNELS=true` позволяет обнаруживать каналы, но не подтверждает их автоматически. Не включайте `CLOUD_DISCOVERY_AUTO_PUBLIC_CHANNELS` без отдельной оценки.
- Сбор комментариев: `CLOUD_COMMENTS_ENABLED=false` по умолчанию. Для активации укажите `CLOUD_COMMENTS_CHANNEL_IDS` — положительные числовые IDs **только выбранных каналов**, ограничьте `CLOUD_COMMENTS_MAX_POSTS_PER_SCAN` и `CLOUD_COMMENTS_MAX_PER_POST`. Новые таблицы создаёт collector, не read-only dashboard.
- Sherlock: `SHERLOCK_OSINT_ENABLED=false` по умолчанию. При включении нужен случайный `SHERLOCK_WORKER_TOKEN` длиной не менее 32 символов. История хранится в отдельном SQLite до 30 дней. Внешние сайты могут возвращать ложные совпадения; результаты не определяют личность.
- **ID автора** — лишь технические метаданные Telegram; это не доказательство угрозы, правонарушения или конкретной личности. Для анонимных сообщений оставляйте ID пустым.
- API и Dashboard должны оставаться доступны через SSH-туннель/контролируемую сеть с авторизацией. Нельзя публиковать `.env`, Telegram session, дампы БД, приватные ключи и токены.
- Перед переключением рабочей версии выполните на Hetzner изолированный бэкап PostgreSQL, проверьте восстановление, миграцию `messages.sender_user_id`, версии Docker/Compose и роли БД. Файл `deploy/compose.reference.yml` — **не работающая конфигурация Hetzner**; в исходном архиве отсутствовала актуальная папка `deploy/`.

## Ограничения автономной проверки

Автономные тесты используют SQLite, заглушки Telethon, FastAPI TestClient и не выполняют реальных запросов Telegram/OpenAI/Sherlock. Ветки и PR — **черновики**, production-контейнеры/БД не менялись. Sherlock не запускается автоматически по событию Telegram и не обогащает сообщения личными профилями.

## Изоляция контейнера Sherlock

Справочный Compose использует `profiles: [sherlock]`: при обычном
`docker compose up` отдельный контейнер не запускается. Для включения нужны
отдельный случайный токен, проверенная сборка Docker и явный профиль
`--profile sherlock`. Если сервис отсутствует или токен не задан, API
отвечает 503 (а не пытается обращаться к открытым сервисам). Версия
`sherlock-project==0.16.2` зафиксирована в отдельном Dockerfile, но
сборка образа на действующем сервере и реальные внешние сайты **не проверены**.

## Каталог возможностей и серверная предварительная проверка

- Полный перечень возможностей, статусов и ограничений: [ВОЗМОЖНОСТИ_TelegramMonitor_RU.txt](ВОЗМОЖНОСТИ_TelegramMonitor_RU.txt).
- Для безопасной проверки состава **локальной копии конфигурации**, не читая секреты: `python scripts/preflight_deploy.py --root .`.
- Для проверки перед выпуском с ненулевым кодом при отсутствующих файлах: `python scripts/preflight_deploy.py --root . --strict`.
- Проверка охватывает только наличие файлов (никаких внешних запросов) и **не заменяет** Docker/DB/Telegram/OpenAI тесты; не публикуйте `.env` или сессии в GitHub.
- Ветка содержит только справочный `deploy/compose.reference.yml`, который не считается рабочей конфигурацией Hetzner.

Sherlock выполняет поиск по username. Телефон, email и ФИО требуют отдельных
источников; совпадения не подтверждают личность или владельца контакта.

а не обещать получение всей информации о человеке.
