## SEARCH-01: начат технический контракт

- Отдельный opt-in параметр поиска; обычный поиск сохраняет прежнее поведение.
- Использовать существующий ru-context-v1; сохранять исходные текст, summary, ID и score. Подмена букв сама по себе не повышает угрозу.
- Ограничивать число кандидатов и длину обрабатываемого текста. В ответе явно сообщать ограниченность охвата и версию; не выдавать ограниченную выборку за поиск по всей истории.
- Сохранять фильтры источников/времени и авторизацию; SQL только параметризованный. Производные значения не переписывают messages.text.
- До выбора индекса измерить стоимость на изолированной копии PostgreSQL. Не запускать полный Python-normalize scan всех строк на каждый запрос.
- Обязательные проверки: найденная смешанная русская форма; оригинальная кириллица; неизменность URL/email/username и армянского текста; disabled/missing dependency; пагинация и ограничения; отсутствие утечки между фильтрами; прежние API и группа1000.
- Этапы готовности: код → unit/API → PostgreSQL stage → Chromium → свежий backup и проверенный rollback → production. Сейчас выполнена постановка контракта, код поиска ещё не изменён.

## Правила ведения

Для каждой новой задачи фиксировать источник, зависимость, код/интеграцию/тесты/stage/production/rollback, ссылку на проверку и следующий шаг. Исторические журналы не удалять. Блокеры внешних API, аккаунтов, стоимости или ресурсов отмечать отдельно; не объявлять ссылки поисковиков серверной интеграцией. Чужие проекты, сессии, секреты, права и лимиты расходов вне области изменений.
