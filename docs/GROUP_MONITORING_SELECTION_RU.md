# Выбор групп для мониторинга — TelegramMonitor v8.6.1

## Возможности

Раздел **«Выбор групп и каналов для мониторинга»** в Dashboard показывает источники
из Telegram-аккаунта, поиск по названию, @username и ID, фильтры и кнопки
**«Включить мониторинг» / «Отключить мониторинг»**. Изменения сохраняются в
`tm_discovered_sources.status`, фиксируются в `tm_source_audit` и вступают в
силу на следующей итерации Collector без его перезапуска. История ранее
собранных сообщений и комментариев не удаляется. Удалённые из аккаунта
источники (`left`) нельзя включить до повторного присоединения/одобрения.

Коллектор использует один снимок статусов для отбора источников:
- `approved` — явно разрешено.
- `disabled` и `left` — запрещено, **даже если источник прописан в статической конфигурации**.
- `pending` и `baseline` — не подключаются автоматически; при старом
  режиме ранее настроенные статические источники продолжают собираться, пока
  пользователь явно не отключит их.

**Строгий режим** `CLOUD_SOURCE_SELECTION_STRICT=true` разрешает ТОЛЬКО
`approved`-источники, включая статически настроенные. По умолчанию он
выключен во избежание неожиданной остановки существующего мониторинга.
Перед включением строгого режима необходимо отметить нужные источники в UI.

## Принцип минимальных прав доступа

Рабочий Dashboard продолжает использовать роль PostgreSQL только для чтения
при показе статистики, сообщений, комментариев и источников. Для изменения
выбора используется **отдельная роль**, которая может читать ID/статусы
источников, менять **только колонку status** и добавлять строки в журнал
аудита. Не предоставлять ей права на сообщения, чекпоинты, комментарии,
бюджеты или OpenAI-запросы.

Ниже пример **для администратора PostgreSQL**, а не команда для
безусловного выполнения на продакшене:

```sql
-- Пароль создать случайным, сохранить только в root-owned env файле.
CREATE ROLE tm_v861_source_controller LOGIN PASSWORD '<СЛУЧАЙНЫЙ_ПАРОЛЬ>';
GRANT CONNECT ON DATABASE monitor TO tm_v861_source_controller;
GRANT USAGE ON SCHEMA public TO tm_v861_source_controller;
GRANT SELECT (peer_id, status)
    ON TABLE public.tm_discovered_sources TO tm_v861_source_controller;
GRANT UPDATE (status)
    ON TABLE public.tm_discovered_sources TO tm_v861_source_controller;
GRANT INSERT (id, peer_id, actor, action, from_status, to_status, changed_at)
    ON TABLE public.tm_source_audit TO tm_v861_source_controller;
```

В конфигурацию Dashboard добавить (секрет не печатать в журнал или в GitHub):

```dotenv
CLOUD_DISCOVERY_ENABLED=true
CLOUD_DISCOVERY_UI_WRITE=true
CLOUD_SOURCE_CONTROL_DATABASE_URL=postgresql+psycopg://tm_v861_source_controller:<URL_ENCODED_PASSWORD>@<DB_DNS>:5432/monitor
```

`DATABASE_URL` Dashboard оставить **неизменным и только для чтения**.
Не переиспользовать полномочия Collector и не выставлять Dashboard в интернет.
Разрешён только доступ через существующий SSH-туннель и HTTP Basic.
Если `CLOUD_SOURCE_CONTROL_DATABASE_URL` отсутствует, интерфейс остаётся
**только для просмотра**, а POST возвращает 403.

Для новых публичных групп включение может происходить автоматически, если
`CLOUD_DISCOVERY_AUTO_PUBLIC=true`. Для ручного выбора **всех**
новых источников установить на Collector:

```dotenv
CLOUD_DISCOVERY_AUTO_PUBLIC=false
CLOUD_DISCOVERY_AUTO_PUBLIC_CHANNELS=false
```

После выбора групп по желанию включить на Collector:

```dotenv
CLOUD_SOURCE_SELECTION_STRICT=true
```

Не включать это значение до первого успешного сканирования и ручного
одобрения источников, иначе Collector в строгом режиме намеренно прекратит
сбор из невыбранных групп.

## Применение в production

1. Протестировать изменения в отдельном окружении; без обновления рабочего
   Collector и Dashboard пока что новой функции на сервере нет.
2. Создать отдельную минимально привилегированную DB-роль по инструкции выше.
3. Проверить `GET /api/sources` (Basic auth), затем `POST /api/sources/{peer_id}`
   с `Origin` равным URL панели, `Content-Type: application/json`,
   `X-TM-Action: 1` и JSON `{"action":"approve"}`/`{"action":"disable"}`.
4. Убедиться, что `POST` без правильного `Origin` получает 403.
5. На тестовой группе проверить, что «Отключить» предотвращает получение
   новых сообщений и повторную синхронизацию, включая статически заданный ID.
6. Сохранить архив и откатные версии контейнеров; заменить рабочие контейнеры
   только после проверки. **Не запускать второй Collector** параллельно с
   рабочим из-за единственной Telegram-сессии.

Панель не может отменить сообщения, уже сохранённые в БД или переданные в
очередь Worker до отключения. Выбор контролирует **будущий сбор**.
