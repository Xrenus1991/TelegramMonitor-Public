TELEGRAMMONITOR — ПЕРЕЧЕНЬ ВОЗМОЖНОСТЕЙ
Дата: 03.11.2026. Проверены исходники GitHub: Xrenus1991/TelegramMonitor,
ветки audit/import-2026-11-03 и feature/v861-comments-sherlock.
Версия разрабатываемой панели: v8.6.1.

ВНИМАНИЕ: наличие функции в GitHub и прохождение автономных тестов
НЕ означают, что она установлена и работает на сервере Hetzner.

Условные обозначения:
[КОД] — реализовано в репозитории; реальная работа ещё не подтверждена.
[ОПЦИЯ] — требует отдельного разрешения/настройки, может быть выключено.
[ОГР.] — ограниченная реализация, не универсальная функция.
[СЕРВЕР] — обязательно проверить в действующей среде Hetzner.
[ПЛАН] — подтверждённой готовой реализации пока нет.

1. СБОР TELEGRAM-СООБЩЕНИЙ
[КОД][СЕРВЕР] Подключение к Telegram через Telethon и загрузка сообщений
из доступных групп и выбранных каналов.
[КОД][СЕРВЕР] Загрузка ограниченной истории при первом запуске.
[КОД][СЕРВЕР] Регулярное получение новых сообщений по расписанию.
[КОД][СЕРВЕР] Догрузка пропусков после разрывов связи (catch-up).
[КОД] Дедупликация по идентификатору источника и сообщения.
[КОД] Ограничение объёма истории, числа сообщений за проход и повторные
попытки при временных сбоях; обработка лимитов Telegram.
[ОГР.] Подключается только к источникам, доступным используемому
Telegram-аккаунту. Обход закрытых чатов не реализован.
[ОГР.] Облачный анализ сосредоточен на текстах; автоматическое
распознавание содержимого фото/видео (OCR/vision) не подтверждено.

2. ОБНАРУЖЕНИЕ И УПРАВЛЕНИЕ ИСТОЧНИКАМИ
[КОД][СЕРВЕР] Просмотр доступных диалогов и обнаружение новых групп.
[ОПЦИЯ][СЕРВЕР] Обнаружение публичных новостных broadcast-каналов
(отдельные параметры CLOUD_DISCOVERY_INCLUDE_CHANNELS и др.).
[КОД] Реестр: Telegram peer ID, название, тип, видимость, статус.
[КОД] Статусы: baseline, pending, approved, disabled, left.
[КОД] Подтверждение, отключение источников через веб-панель и журнал
административных решений.
[КОД] Новые каналы по умолчанию требуют подтверждения.
[ОПЦИЯ] Автоматическое подключение новых публичных каналов предусмотрено,
но по умолчанию выключено; безопаснее подтверждать вручную.
[ОГР.] Это не глобальный поисковик всех каналов Telegram.

3. OPENAI, СВОДКИ И АНАЛИЗ
[КОД][СЕРВЕР] Отдельный облачный worker: OpenAI или режим dry_run.
[КОД] Пакетная классификация текста: релевантность, тема, приоритет
low/normal/high, краткая русскоязычная сводка, указание неопределённости.
[КОД] Выборочный более глубокий разбор, разделяющий изложенные факты,
неподтверждённое и ограничения вывода.
[КОД] Проверка структуры ответов модели, повторы при ошибках.
[КОД] Настройка ограничений: размер пакета, объём текста, глубина анализа,
дневные лимиты, бюджет OpenAI API с учётом резервирования и расходов.
[КОД] Старый локальный модуль допускает выбор Ollama/OpenAI.
[СЕРВЕР] Нужно отдельно проверить правильность названий моделей, ключ,
скорость, реальные расходы, качество классификации и обработку таймаутов.
[ОГР.] Анализ сообщений не устанавливает истинность событий и не является
доказательством угрозы, виновности или намерений конкретного человека.

4. УМНЫЙ ПОИСК, ЯЗЫКИ, ПОХОЖИЕ ПУБЛИКАЦИИ
[КОД] Обнаружение некоторых русских слов, где кириллические буквы заменены
похожими латинскими; очистка отдельных невидимых Unicode-символов.
[КОД] Ограниченные словари транслитераций и вариантов названий
городов/регионов Армении, включая часть армянских написаний.
[КОД] Поиск по словам в обработанных текстах и фильтры по источникам/темам.
[КОД] Поиск повторов и группировка похожих публикаций.
[КОД] Выделение упоминаний некоторых географических названий.
[ОГР.] Оригинальный текст сохраняется; алгоритм не является полноценным
машинным переводчиком и может пропускать нестандартные написания.
[ОГР.] Повтор одного утверждения в разных сообщениях не подтверждает факт.

5. БАЗА ДАННЫХ, УСТОЙЧИВОСТЬ, ID АВТОРА
[КОД] SQL-хранение сообщений, состояния обработки, классификации и итогов.
[КОД] PostgreSQL для облака; SQLite используется для части локальных
компонентов и автономных тестов.
[КОД] Очередь обработки, контрольные точки, повторы после ошибок и
защита от повторного сохранения одного сообщения.
[КОД] Сохранение Telegram User ID, если Telegram явно сообщает PeerUser.
[КОД] ID показывается в обработанных событиях, ежедневной сводке и сигналах.
[КОД][СЕРВЕР] Подготовлена добавочная миграция messages.sender_user_id;
сначала требуется резервное копирование и проверка на копии PostgreSQL.
[ОГР.] Для публикаций от имени каналов и анонимных администраторов ID
конкретного пользователя неизвестен; старые записи автоматически не обогащаются.
[ОГР.] Telegram ID — метаданные, а не надёжная идентификация личности.

6. АНАЛИТИЧЕСКИЕ МАТЕРИАЛЫ
[КОД] Ежедневная сводка обработанных сообщений за сутки UTC.
[КОД] Сигналы с эвристической сортировкой и ручной проверкой.
[КОД] Выявление похожих/повторяющихся сообщений за период.
[КОД] Постраничный поиск по событиям, фильтры по теме/источнику.
[КОД] Статистика обработки, диагностические счётчики и список источников.
[ОГР.] Материалы информационные, не автоматические юридические выводы.

7. КОММЕНТАРИИ ПОД НОВОСТНЫМИ ПОСТАМИ (ВЕТКА v8.6.1)
[ОПЦИЯ][СЕРВЕР] Сбор комментариев только из явного списка разрешённых
каналов (CLOUD_COMMENTS_ENABLED=false по умолчанию).
[КОД] Привязка комментария к исходному посту и discussion-группе.
[КОД] Отдельные таблицы комментариев и журнала сканирования.
[КОД] Ограничения количества источников, постов, комментариев и срока хранения.
[КОД] Повторные сканирования без дублирования данных.
[КОД] Обзор обсуждений, просмотр ветки, поиск кандидатов на ручную
проверку возможных прямых угроз.
[КОД] Осторожные текстовые эвристики; авторский User ID сохраняется для
кандидатов только при подтверждённом PeerUser.
[КОД] Простая маскировка телефонов/e-mail/@упоминаний в выдаче.
[ОГР.] Маскировка не гарантирует полной анонимности, а флаг угрозы
не означает фактической угрозы. Нельзя автоматически приписывать человеку вину.
[СЕРВЕР] Нужно проверить доступ Telegram-сессии к реальным обсуждениям.

8. SHERLOCK — ПОИСК ПУБЛИЧНЫХ ИМЁН (ВЕТКА v8.6.1)
[ОПЦИЯ][СЕРВЕР] Ручной поиск открытых совпадений по username
через отдельный изолированный сервис.
[КОД] Создание задания и просмотр статуса/истории через защищённую панель.
[КОД] Отдельное хранилище SQLite и срок хранения истории до 30 дней.
[КОД] Контроль числа параллельных запросов, валидация имени и токен доступа.
[КОД] Исправлен сбой при отказе очереди исполнителя: статус failed вместо
бесконечного queued; есть отдельный регрессионный тест.
[КОД] В справочном Compose: отдельная сеть, ограниченные права, отключён
по умолчанию; отсутствует доступ к Telegram/OpenAI секретам.
[ОГР.] Похожие username не доказывают общую личность; автоматической
идентификации по Telegram User ID не существует.
[СЕРВЕР] Реальная Docker-сборка и доступ к внешним сайтам не проверены.

9. ВЕБ-ПАНЕЛЬ И ПРОГРАММНЫЙ API
[КОД] Защищённая паролем веб-панель: состояние базы, источники,
анализ событий, поиск, повторы, дневные сводки и сигналы.
[КОД] Дополнительные разделы комментариев и Sherlock в ветке 8.6.1.
[КОД] Маршруты /health, /api/stats, /api/events, /api/filters,
 /api/diagnostics, /api/analytics/duplicates, /api/analytics/daily,
 /api/analytics/signals, /api/sources, /api/sources/audit.
[ОПЦИЯ] /api/comments/overview, /api/comments/thread,
 /api/comments/alerts; /api/osint/sherlock/jobs и /recent.
[КОД] Опция управления статусами источников через API при наличии прав.
[КОД] Референсный Docker Compose привязывает веб-порт к 127.0.0.1;
предполагается ограниченный сетевой доступ (например, SSH-туннель).
[СЕРВЕР] Авторизация, браузерное отображение и фактические порты Hetzner
требуют отдельной реальной проверки.

10. ЛОКАЛЬНАЯ ВЕРСИЯ ДЛЯ MAC / ТЕРМИНАЛА
[КОД] Текстовый интерфейс Textual: лента сообщений, панель медиа,
аналитическая сводка, строка состояния.
[ОПЦИЯ] Скачивание фото, видео, GIF и документов в пределах лимита размера,
подписи к медиа и локальное отображение.
[КОД] Локальные конфигурации и мастер настройки.
[ОГР.] Это терминальная программа, не готовое отдельное установочное
приложение для macOS/Windows.

11. КАЧЕСТВО И БЕЗОПАСНОСТЬ
[КОД] Автономные pytest, контроль Python-синтаксиса,
JavaScript панели и справочных границ изоляции Docker.
[КОД] Предварительный скан типовых секретов, исключение сессий,
дампов БД, паролей и резервных копий из Git.

не тестировались вместе; реальная серверная готовность НЕ установлена.

без ручной проверки и подтверждения.

[ПЛАН] Полноценный анализ содержимого видео/фото в облачном модуле.
[ПЛАН] Поиск абсолютно всех Telegram-каналов, обход закрытых обсуждений.
[ПЛАН] Автоматическое достоверное установление личности, вины или
