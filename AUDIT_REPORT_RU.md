## Существенные ограничения / открытые задачи

1. Отсутствуют реальные и обезличенные региональные `configs/*.json`, в том
   числе `configs/armenia_groups_osint_pro.json`, необходимый облачной конфигурации.
   Существующий сервис на сервере продолжает использовать свои файлы.
2. Не приложены `deploy/`, Docker/Compose, настройки служб и схемы PostgreSQL.
   Нельзя утверждать, что вся производственная конфигурация проверена.
3. **Исправлено в коде, но ещё не развёрнуто на Hetzner:** добавлено
   необязательное поле `sender_user_id`. Сборщик сохраняет ID **только** когда
   Telegram явно указывает `PeerUser`. Анонимные сообщения и публикации от
   имени канала остаются без ID пользователя: ID канала нельзя выдавать за ID
   физического лица. Поле добавлено в API событий, ежедневные сводки и
   сигналы. Миграция старой БД выполняется при инициализации пишущего `Store`;
   история не удаляется. Старые записи по умолчанию останутся с `null`, пока
   явно не будут повторно получены с достоверными сведениями об авторе.
   Наличие ID автора не подтверждает достоверность сообщения или виновность.
4. В облачной версии новостные каналы требуют `CLOUD_DISCOVERY_INCLUDE_CHANNELS`,
   а автоматическое утверждение открытых каналов по умолчанию отключено.
   Это проверено по коду, не по переменным окружения VPS.
5. Для группы комментариев к каналу не обнаружена отдельная логика связывания
   комментариев с постами. Наличие событий в связанной группе зависит от
   подключения и разрешения самой группы; требуется интеграционный тест.
6. Лимиты запросов и стоимость OpenAI нужно перепроверить на действующей
   учётной записи и реальной конфигурации, не запуская платные тесты без согласия.
7. README ссылается на документы, исключённые из снимка. Их необходимо
   восстановить из полной очищенной сборки или обновить документацию.

## Осторожность при развёртывании

Не копировать тестовый JSON в боевой `configs/`, не подменять env-файлы,
не изменять схему PostgreSQL и не перезапускать сервисы до проверки на
тестовом окружении. Все действия с живым сервером требуют отдельного
регламентированного этапа.

## Обновление схемы и безопасный выпуск (`sender_user_id`)

Перед деплоем создать **отдельную** резервную копию PostgreSQL и проверить
процедуру восстановления. Обновлять работающую систему только после анализа
файлов `deploy/` на VPS: в данном снимке их нет. При инициализации пишущего
`Store` колонка добавляется автоматически: для PostgreSQL `ALTER TABLE
messages ADD COLUMN IF NOT EXISTS sender_user_id BIGINT`, для SQLite
аналогичный безопасный добавочный столбец. Dashboard использует read-only
подключение и **не** выполняет миграции; его новую версию запускать после
успешной миграции пишущим компонентом.

Отсутствующие ID авторов ранее сохранённых сообщений не следует заполнять
вычислением по названию группы, `channel_id`, `message_id`, пересылке или
предположению модели. Публикации без проверяемого `PeerUser` показываются
без ID автора. Автономные тесты проверены в SQLite; PostgreSQL на VPS и
действующие Telegram-данные ещё не проверялись.
